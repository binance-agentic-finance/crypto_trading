## Read this before choosing a node

**Availability is not a footnote — it decides whether your strategy can be backtested at all.** Most internal snapshot endpoints (Square social, futuresRadar, movement) are Redis-TTL reads with no point-in-time history. Replaying one reuses *today's* value at every historical bar, which produces a confident and completely fictional equity curve.

| tier | meaning | allowed in backtest |
|---|---|---|
| `BACKTESTABLE` | real history, deep enough to walk forward | yes |
| `SEMI` | history exists but is windowed / shallow / publication-lagged | only within the available window — check the first timestamp |
| `FORWARD_ONLY` | snapshot only — no replayable history; collect forward | no — live/paper only, strategy is RESEARCH_ONLY |
| `EXTERNAL_PENDING` | contract specified, feed not onboarded | no — feed not onboarded |
| `NOT_WIRED` | no endpoint exists anywhere | no |

`data.validate_nodes([...], for_backtest=True)` enforces this at compile time and quotes the specific hazard, so the failure lands before the run rather than as a flat curve after it.

**An empty result is not `ok`.** The Square APIs are Prod IP-whitelisted and answer off-whitelist calls with `success: true` and an empty body — indistinguishable from "nothing happened" unless the status is carried separately. Every call routes through the catalog, which grades an empty frame as `degraded`, never as zero.

## Kline / technical

### `data.klines`

OHLCV candlesticks — the base series every technical block reads.

- **availability**: `BACKTESTABLE` — real history, deep enough to walk forward
- **source**: Technical Indicator API (base URL from `$INDICATORS_URL`)
- **endpoint**: indicators service (base URL from $INDICATORS_URL); public: data-api.binance.vision, api.binance.com/api/v3/klines, fapi/v1/klines
- **substitute**: cyqnt_trd.data_cli.fetch_klines (public Binance)
- **returns**: `pd.DataFrame` — one row per bar, oldest first · columns: `open_time`, `open`, `high`, `low`, `close`, `volume`, `quote_volume`, `close_time`, `trades`

| param | type | required | default | notes |
|---|---|---|---|---|
| `symbol` | `str` | yes |  | e.g. BTCUSDT |
| `interval` | `str` | no | `'1h'` | bar interval (`1m` / `5m` / `15m` / `30m` / `1h` / `4h` / `1d`) |
| `limit` | `int` | no | `500` | number of rows (most recent last) |
| `market_type` | `str` | no | `'futures'` | spot | futures (USDⓈ-M perpetual) (`spot` / `futures`) |

## Codegen contract

- Call form is `data.<function>(**params)` — the same one-rule derivation the
  compute nodes use, so no mapping table is needed.
- `import` line: `from cyqnt_trd.standard_bot.runtime import data, action`.
- Param keys above are exactly the spec `params[].key` values.
- Wrap a whole decision cycle in `with data.session() as s:` so every node in
  the DAG shares one `as_of`; `s.status_map()` then feeds
  `SnapshotMeta.source_status` and `s.warnings()` feeds `SnapshotMeta.warnings`.
- A failed fetch raises `data.DataUnavailable`; `data.collect([...])` degrades
  instead, returning the frames it got plus the per-node status.

_66 nodes: 6 BACKTESTABLE, 21 SEMI, 30 FORWARD_ONLY, 9 EXTERNAL_PENDING._
