# Gate0 funnel: how much trainable gold is in the 51,595-row corpus

Generated by `tools/nl2yaml/measure.py` (gate0-measure/1) over the whole corpus, **no LLM in the loop**.
Miner: `gate0-mine/1`. Capability table: commit `3e247b01e0f0`, probed 2026-08-02.

Every count is written **rows / unique-canon-texts / split-groups**. Use split-groups as the example count: 43% of the corpus collapses into a group with another row, the largest single group is 1507 rows, and a random split over rows measures memorisation.

## 0. Read this before using any number below

`capability.plan_conversion` needs conditions in its own vocabulary, and producing those is A1's job (an LLM). This pass substitutes a hand-written map from the miner's regex `(family, subject)` pairs onto capability subjects, so **every number here is an UPPER BOUND**. The true yield is strictly lower, for four reasons that all push the same way:

1. **Miner recall is a floor.** The regexes find a subset of a request's conditions. A row scored "all expressible" can still contain an unmined `not_expressible` one - which is exactly the 'exclude tradfi' accident: the blocking condition was in the text and not in the machine's hands.
2. **The map is coarse in the generous direction.** `volume` (a COIN count) is scored against `quoteVolume` (quote currency); `exclude` (the verb) is scored as `symbol_blacklist` without knowing *what* is excluded, because every plausible target happens to be expressible.
3. **`unknown` is forgiven in the headline.** 5318 rows / 3046 groups are "upper bound" only because a `(subject, scope, operator)` the table does not rule on was treated as expressible. The `strict` column removes them; section 5 lists exactly which keys they are.
4. **Scope is guessed for ambiguous rows.** `classify_request` returns ambiguous for 32815 rows. Those are scored in both frames and the better result kept - upward again.

A fifth, separate discount: expressible is not gradeable. See section 7.

Two things push the other way and are stated so they can be argued with:

* **The gap ranking cannot rank 14 of the table's 16 gap ids** (section 5). Most lack a miner detector, so requests that hit them are scored as clean and refusal-gold counts are floors. The list also retains historical ids whose capability is now closed; those have zero counts by design.
* **Two intervals in one conversation are scored as a resonance request.** The miner reads the whole excerpt, so "look at 1h ... now 4h" is indistinguishable from "aligned on 1h AND 4h", and only the second needs the missing capability. That pushes rows OUT of the upper bound, which is the wrong direction, so the size of the effect is stated rather than argued: 0 selection / 744 trade rows (0 / 525 groups) are blocked by nothing else and would flip back into the bound if the heuristic is judged wrong.

## 7. Is this enough to fine-tune? (500-5,000 structured outputs)

The two base dialects remain separate (`selection:` ranks a universe; `signals:` emits per-bar entries for one declared symbol). A compound request does not put both sections at the top level: it is an outer `selection:` whose candidates carry `candidate_trade`. The three training shapes are therefore counted apart:

| dialect | scored rows | upper bound rows | **upper bound, deduped (groups)** | + >=1 expressible (groups) | minus overstated (groups) | strict (groups) | + user stated every number (groups) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| selection | 1784 | 1012 | **740** | 686 | 668 | 606 | 456 |
| trade | 12210 | 10105 | **6899** | 6800 | 5974 | 5726 | 3623 |
| compound selection | 2427 | 2208 | **1415** | 1415 | 983 | 916 | 493 |

The last column adds "and the user stated every number the spec needs" (families ['risk', 'rank_topn'] must carry a value). It is not a nicety: an expressible-but-unquantified `add a stop-loss` forces the annotator to pick the percentage, and a gold spec whose stop was invented by the annotator trains the model to invent stops. 15466 of the corpus's risk conditions carry no value at all.

`both` is shown as compound selection because it now has a concrete target grammar. `unclear` (31919 rows) remains excluded: it has no decided shape, so its target dialect would be the annotator's guess.

Refusal gold remains a third, cheaper class:

| dialect | refusal gold rows | deduped (groups) |
| --- | --- | --- |
| selection | 128 | 110 |
| trade | 853 | 606 |
| both | 219 | 105 |
| unclear | 213 | 177 |

A refusal is not a consolation prize. It is the output that stops the accident this dataset exists because of: the gap vocabulary is closed, so a refusal is graded by string equality against an id known before generation, and grading it costs nothing and cannot drift. Both dialects need one.

### The answer

**Trade dialect: yes, with room to spare - the problem there is selection pressure, not scarcity.** 6899 distinct requests clear the bound, 5726 survive the strict reading, and 3623 also have every number the user stated rather than an annotator's guess. The band is 500-5,000; the tightest of those columns is already inside it, so the trade set can be cut for quality (quantified, tier A/B, one row per split group) instead of scraped for volume, and a genuine held-out test set is affordable.

**Selection now has two strata, so the old single 'no' no longer follows.** The ranking-only shape has 740 upper-bound split groups and 110 refusal groups. Compound selection contributes another 1415 upper-bound groups via `candidate_trade` (916 strict; 493 with every required number stated). They share an outer `selection:` grammar but not target complexity, so report and hold them out separately rather than adding them into one headline.

Three next moves follow from the refreshed capability boundary:

1. **Decide the shape of the ambiguous rows.** `classify_request` returns `ambiguous` for 32815 of 51595 rows, and that bucket holds 6062 upper-bound distinct requests with no dialect assigned - more than the trade dialect yields in total. Only 2313 rows in the whole corpus are classified `selection` at base. Sharpening the classifier (or letting A1 decide the shape and recording its choice as a field) is a cheaper move than any block, and it is where the selection examples are hiding.
2. **Curate compound selection as its own stratum.** 1415 upper-bound split groups now have a concrete target: one outer basket with a confirmation-required nested trade per candidate. Keep golden examples explicit about `candidate_trade`, exits, sizing, and the no-auto-trade boundary.
3. **Keep the remaining `GAP-PER-SYMBOL-INDICATOR` claim narrow.** It now blocks 550 distinct requests, 525 by itself. The surviving row is per-symbol multi-timeframe resonance; cross-sectional per-candidate indicators already use `universe.augment_with_indicator`, so this gap no longer describes a compound-selection limitation.

**One practical note on cost.** A1 does not need 51595 calls. Conditions are computed per unique canonical text and cases split by group, so one pass over the 16472 candidate split groups covers the 26161 candidate rows - a 1.6x saving - and it is also the only way the train/test split stays honest.

**And one warning about what this pass cannot tell you.** Section 5 sees 2 of 16 gaps; the unranked set mixes missing miner detectors with historical ids retained after closure. Miner recall is still a floor, so refusal counts are floors and spec counts are ceilings. The number that would settle it is the one this pass deliberately did not spend: run A1 over a stratified sample of a few hundred split groups, have a human adjudicate every condition, and compare the realised level-5 rate against the 83% and 57% upper bounds in the shape table. Until then, treat the trade 'yes' as firm, and treat ranking-only versus compound selection as separate measured strata rather than reviving the old single 'no'.
