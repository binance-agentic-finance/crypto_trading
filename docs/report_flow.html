一份 JSON 進,一種訊號出

統一輸入 cyqnt.input/v1 → blocks 組策略 → 統一輸出 cyqnt.signal/v2

本頁所有數字都是實跑抓的(docs/gen_report_html.py)。系統架構、哪條路活著、已知缺口見 docs/ARCHITECTURE.md;I/O 規格全文見 strategies/_standard/ 底下的兩份 schema。

核心一句話
一次取數變成一份 JSON,用積木組出策略,輸出一種格式 —— 交易和選幣共用同一份 schema,消費端只認一個 kind 欄位。

0. 全流程

① 取數 ② 組策略 ③ 出訊號 ④ 消費 ────────────────────────────────────────────────────────────────────────────────── K 線 ┐ ┌─ kind=trade ┌→ 回測 ✅ funding / OI ┤ │ │ 清算 ┤→ 一份 JSON → blocks 積木 → ┼─ kind=selection ┼→ paper ✅ 新聞 / 熱度 ┤ cyqnt.input/v1 (393 個積木) │ │ 選幣宇宙 ┤ └─ kind=alert └→ live ⚠️ 內部節點 ┘ cyqnt.signal/v2 ▲ 一個決策時點 ▲ YAML 或 Python ▲ 交易與選幣同一格式 所有來源 不寫程式也能組 消費端只認 kind 一個欄位 PIT 只 gate 一次

1. 輸入 —— 一個時間點、所有來源、一份 JSON

格式 cyqnt.input/v1,契約檔 strategies/_standard/input.schema.v1.json。兩個產生器吐出完全相同的 envelope,所以 paper 讀到的檔案形狀和回測一模一樣:

產生器用途
build_live_bundle()打 API 取即時資料(paper / live)
build_input_bundle()讀本地檔(回測 / 回放)

1.1 三個設計不變量

  • 一個時鐘 —— 每一列在寫進 JSON 前都過 available_time <= decision_time。 只 gate 一次,下游不可能再讀到未來。event_time(事情何時發生)與 available_time(我們何時才可能知道)是兩個不同欄位,混為一談就是 walk-forward 偷看未來的來源。
  • 一套詞彙 —— funding / OI / 清算 / 任何內網數值,全部落成同一種 MetricFrame:(instrument_id, metric, value, event_time, available_time)。 策略讀三個來源用同一個存取函式,加第四個來源不用改管線。
  • 一個窗 —— 每條序列只留最新 N 筆。同一份 bundle 從 1.7 MB 降到 158,779 bytes,策略輸出完全不變。

2. 組策略 —— blocks 積木,YAML 不寫程式

blocks/ 有 393 個純函式(指標、條件、衍生品、新聞、選幣、風控…),策略就是這些積木的組合。YAML 可觸及 362 / 393 個。

2.1 交易策略(多來源)

# =============================================================================
# 範例 3 —— 多來源(OHLCV + 資金費率 + 未平倉量)
# =============================================================================
# 前兩個範例只用 K 線。這一個示範怎麼把「不是 OHLCV 的資料」接進策略:
#
#   data.derivatives:  → 掛上 funding_rate / funding_rate_bps / mark_price /
#                        open_interest / open_interest_value / oi_change_bps
#   data.liquidations: → 掛上 long_liq_notional_usd / short_liq_notional_usd /
#                        net_liq_notional_usd / liq_imbalance_ratio ...
#
# 三個要點:
#   1. 沒有宣告 data.derivatives 就引用 funding_rate_bps → validate 直接擋下來,
#      並告訴你要加哪一段。不會讓你驗證過了才在跑的時候拿到 NaN。
#   2. derivatives.* 這一類 block 吃的是「具名 Series」而不是整個 df,
#      所以用 input: <欄位或前面算過的指標名>;要兩個 Series 就用 inputs: [a, b]。
#   3. 指標可以串接:後面的指標可以用前面指標的「名字」當 input。
#
# 執行:
#   驗證:  python -m cyqnt_trd.standard_bot.yaml_pipeline validate example_multi_source.yaml
#   回測:  python -m cyqnt_trd.standard_bot.yaml_pipeline run example_multi_source.yaml
# =============================================================================

spec_version: "1.0"
target: standard_bot

strategy:
  id: btc_multi_source
  description: "BTC:EMA 金叉 + 資金費率為負(空方在付錢) + 未平倉量沒在暴衝 → 做多"

run:
  mode: backtest

data:
  symbol: BTCUSDT
  market_type: futures                # 衍生品資料只有 futures 有
  primary:
    # repo 內的 parquet 只有 1m;要跑 1h 有兩條路:
    #   (a) 放一份 1h parquet 進 data.source.dir,或
    #   (b) 用 --engine event,它會依 source.storage_timeframe 自行 resample
    #       (預設的向量化引擎不會 resample)
    interval: "1m"
    poll_interval: 3570
  source:
    type: historical_parquet
    dir: data/mtf_90d
  derivatives:                        # ← 資金費率 + 未平倉量
    dir: data/derivatives_mvp_30d
  # liquidations:                     # ← 清算(要用再打開)
  #   dir: data/liquidations_mvp_live

signals:
  indicators:
    ema_fast: { block: indicators.ema, input: close, params: { period: 60 } }
    ema_slow: { block: indicators.ema, input: close, params: { period: 240 } }

    # 吃 df 掛上來的 funding 欄位,回傳分類字串 Series
    fund_state:
      block: derivatives.funding_rate_state
      input: funding_rate_bps
      params: { high_threshold_bps: 1.0, low_threshold_bps: -1.0 }

    # 吃 open_interest 欄位,回傳 12 根期間的變動百分比
    oi_chg:
      block: derivatives.oi_change_pct
      input: open_interest
      params: { periods: 12 }

    # 指標串接:atr 先算,再餵給 regime 判斷波動位階
    atr14:  { block: indicators.atr, input: df, params: { period: 14 } }
    vol_hi: { block: regime.atr_above_percentile, input: atr14,
              params: { window: 200, percentile: 0.8 } }

  entry:
    long:
      all_of:
        - { cond: conditions.ma_cross_above, args: [ema_fast, ema_slow] }
        # 數字字面量原樣傳入(不會被包成 Series);名字則解析成 Series
        - { cond: conditions.value_below,    args: [funding_rate_bps, 0.0] }
        - { cond: conditions.value_below,    args: [oi_chg, 5.0] }
        # 波動過高時不進場
        - not: { cond: conditions.value_above, args: [vol_hi, 0.5] }
    short:
      all_of:
        - { cond: conditions.ma_cross_below, args: [ema_fast, ema_slow] }
        # 分類 Series 要用 state_equals,數值比較會直接丟 TypeError。
        # 字串常數放 params ——「args 裡的字串」一律當成欄位/指標名解析。
        - { cond: conditions.state_equals,   args: [fund_state],
            params: { state: "bullish_squeeze" } }

sizing:
  size: 0.5

risk:
  exit:
    type: atr_stop_tp
    atr_period: 14
    stop_mult: 2.0
    tp_mult: 4.0
    max_bars: 120
  fees: { commission_bps: 4.0, slippage_bps: 2.0 }

backtest:
  initial_capital: 10000
  execution_model: next_bar_open
validate: 通過 —— 靜態檢查 + 用合成資料實跑一次

兩道保護:

  • 沒宣告 data.derivatives 就引用 funding_rate_bps → validate 直接擋,並告訴你要加哪一段。不會驗證過了才在跑的時候拿到空值
  • validate 會用合成資料實跑一次,抓出參數名錯、型別錯、arity 錯。過了 validate 就是結構上可跑

實跑結果(真實資料)

資料來源: parquet(1m.parquet)+derivatives(+6)
K 線:     129,599 根
掛上的衍生品欄位: oi_timestamp, open_interest, open_interest_value, oi_change_bps, funding_timestamp, funding_rate, funding_rate_bps
funding 有值的根數: 30,234
反事實檢查 —— 多源資料真的在起作用
只留 EMA 交叉 → 345 個做多訊號;加上 funding + OI 條件 → 36 個。濾掉 309 個(89.6%)。資料不是掛在那裡好看的。

2.2 選幣策略(截面)

signals: 逐根評估一個標的 → kind=trade;selection: 一次評估整個宇宙 → kind=selection。兩者互斥,一份 spec 只能是其中一種。

# =============================================================================
# 範例 4 —— 選幣(cross-section)
# =============================================================================
# 前三個範例都是「單一標的、逐根 K 線」。這一個是另一種形狀:
# 一次對整個幣種宇宙排名,輸出一籃候選,而不是某一根 K 的多空。
#
#   signals:   → 逐根評估一個標的      → kind=trade
#   selection: → 一次評估整個宇宙      → kind=selection
#   兩者互斥,一份 spec 只能是其中一種。
#
# 語法完全共用:selection 的 frame「一列是一個幣」而不是「一列是一根 K」,
# 所以 features / long_when 用的是同一套 block 與同一套比較器。
#
# 執行:
#   驗證:  python -m cyqnt_trd.standard_bot.yaml_pipeline validate example_selection.yaml
#   跑一次:python -m cyqnt_trd.standard_bot.yaml_pipeline run example_selection.yaml
#
# 注意 run.mode:選幣是「一個時點對整個宇宙排名」,沒有逐根 K 的權益曲線,
# 這個 repo 也沒有截面回測引擎。所以 run 會實際跑一次選幣、印出籃子並輸出
# cyqnt.signal/v2,而不是回測 —— 它會明講這件事,不會給你一條 trades=0 的假回測。
# =============================================================================

spec_version: "1.0"
target: standard_bot

strategy:
  id: news_buzz_selector
  description: "流動性過濾後,依 Square 提及量排名,情緒偏多做多、偏空做空"

run:
  mode: backtest

data:
  symbol: BTCUSDT          # 選幣型仍需宣告一個代表標的(排程與計價用)
  market_type: futures
  primary:
    interval: "1h"

selection:
  universe:                # 依序套用的 universe pipeline;每一步都回傳收窄後的 frame
    - block: universe.filter_quote_volume
      params: { min_quote_volume: 100000000 }
    - block: universe.augment_with_news
      with: [ticker_rank]  # 第二個位置參數:把 ticker_rank frame 餵進去

  features:                # 逐幣的 Series,語法與 signals.indicators 完全相同。
                           # 這裡的「rolling」是沿著幣種排名跑,不是沿著時間 ——
                           # 同一個 block,不同的軸。
    buzz_z:
      block: indicators.rolling_zscore
      input: news_mention_count
      params: { period: 6 }

  score: news_mention_count   # 依這個欄位由大到小排名(欄位或上面算出的 feature 都可以)
  top_k: 5
  min_score: 1.0

  # 同一個資產的不同計價對算「一個名字」。Square 的提及量是按 base token 統計的,
  # 所以同一個分數會 join 到 BTCUSDT / BTCUSDC 每一對上;不去重的話 top_k=5 會變成
  # 「3 個資產佔 5 個位置」,BTC 與 SOL 各拿雙倍權重。同分時留成交額大的那一對。
  # 要做 USDC/USDT 基差之類真的把計價對當不同標的的策略,才設 none。
  dedupe_by: base_asset       # base_asset(預設) | none

  long_when:  { cond: conditions.value_above, args: [news_bull_ratio, 0.55] }
  short_when: { cond: conditions.value_below, args: [news_bull_ratio, 0.45] }
validate: 通過

3.1 兩個關鍵欄位

intent —— 12 種值,明確區分「平多」和「開空」,執行層不用猜:

open_long  open_short  add_long  add_short  reduce_long  reduce_short  close_long  close_short  flip_to_long  flip_to_short  flat  hold

而且沒宣告讀過部位的策略不准發平倉指令 —— 框架直接丟 CapabilityError。理由很直接:那些指令都在斷言「現在有一個部位」,而一支從沒讀過部位的策略是在猜。

exit_plan —— 停損、分批停利、移動停損、時間停損,跟著訊號一起走,不是只活在某個 daemon 的記憶體裡。
