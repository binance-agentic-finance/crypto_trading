Strategy YAML Spec v1 — 設計流程・問題與解法・成果

讓前端 / bdp-ai-trading-bot 用 blocks 組裝策略,一個 YAML 跑 backtest / paper / live
日期 2026-07-22 標的 cyqnt_trd/standard_bot（block path） 狀態 已實作並實跑驗證

0 · 一句話結論

我們不需要新建「評分 / 方向合成 / sizing」層。standard_bot 的 block path（strategy.register + make_signals(df)→(long,short)）本來就能做 多因子、任意巢狀組合、宣告式出場與 sizing,而且 backtest / paper / live 三條路跑完全相同的訊號碼。 這份 YAML 就是把那條路徑「宣告式化」:前端填 YAML → validate 擋錯 → run 上線。

1 · 目標與定案

需求（主管 / Harvin）:一份 YAML 規格,前端依規格用 blocks 排列組合成策略,可 paper / live; bot 最終在 bdp-ai-trading-bot 跑,crypto_trading 提供「YAML → run」執行器。 YAML 要含:數據源 / 每個源拉取週期 / 信號計算 / 方向 / 倉位決策 / 風控 / 真實交易-paper / 執行週期,且可巢狀。

底座定案:走 standard_bot block path,不走 atomic、也不走 typed-plugin path。

候選能否組合全部 blocks評分/巢狀/出場裁決
atomic（demo_strategy）是,但走 compat shim + 平行數值實作有,但 47 個已知 bug參考,不上線
standard_bot typed-plugin否（只 11 個 plugin、一次一個、無評分層）無簡單策略可用
standard_bot block path是（全部 blocks）原生具備,三模式共用✅ 採用

3 · 遇到的問題與解決方案

問題怎麼發現 / 為何是問題解決方案
底座認知錯誤 初版把 standard_bot 只看成 typed-plugin（一次一個、無評分層),因此以為要新建「組合層」。 讀 live-executor.md + blocks/strategy.py,發現 block path 的 make_signals 才是完整組合面,三模式共用 → 改走 block path,省掉整層工程。
環境跑不起來 預設 python3.14 沒有 numpy/pandas/requests,且 ensurepip 壞、建不了 venv。 改用 python3.11 建 venv,pip 裝最小依賴（pandas/numpy/pyarrow/requests/pyyaml）。
import 連鎖缺件 import cyqnt_trd.standard_bot 連鎖到 websockets 缺失而失敗。 補裝 websockets,import 鏈打通。
離線沒有行情資料 要證明「真的能跑」但無把握連得到交易所歷史資料。 用 repo 內 tests/blocks/fixtures/BTCUSDT_1h_500bars.parquet 轉成 --input-json 的 kline JSON,離線端到端跑回測。
子進程註冊不到策略 YAML 策略在主進程 register,但 paper daemon 是獨立進程,拿不到。 寫 _daemon_loader.py,靠環境變數 CYQNT_YAML_SPEC 在子進程 import 時註冊 —— 沿用官方 --strategy-module 機制。
欄位名不一致 validate 檢查 run.duration,但實際欄位是 run.duration_end_at,live 檢查會誤判。 統一為 duration_end_at(ISO8601),validate 與派工同步修正。
純靜態驗證不夠 只檢查「block 存不存在」擋不掉「簽章/參數/型別對不上」—— 正是 Harvin demo 那 47 個 bug 的來源。 validate 加一段合成 OHLCV dry-run:真的跑一遍 make_signals,抓 TypeError: ma_cross_above() missing 1 required argument 'slow' 這類錯,碰真錢前擋下。
套件版本偏移 裝到 pandas 3.0 / numpy 2.x,比 repo 釘選的 <3.0 / <2.0 新。 python 引擎路徑實測可跑;建議 正式部署用 repo 釘選版重驗一次（numba 路徑需釘選版）。
安全風險 機器裝了 binance-cli、有 ~/.binance 憑證目錄;稍有不慎可能誤下真實單。 全程 paper-only:不碰憑證、不下真實單;live 模式只印出安全序列(paper 先行 → 查餘額 → CONFIRM → 時長上限 → dry-run first),CLI 絕不自動下單。

5 · 誠實的邊界

  • live 真實下單未執行（刻意）:註冊 + 派工 + 兩段式指令都驗過,但實際 futures live 需「已驗證 futures CLI + 人工 CONFIRM + 真錢」,不由 agent 自動做;預設仍以 binance-cli spot get-account 為準。
  • validate 的 dry-run 是 fail-fast:一次報第一個致命錯,修完再跑出下一個。
  • 組合面:indicators / conditions / entry / exit / sizing 已接線並實測;verdicts / scoring / smc / patterns 在白名單內、可被 dry-run 逐一驗證,但只實測了常用集合。
  • 多時框（htf）原生支援、dry-run 已驗;離線 --input-json 只有單一時框,htf 腿在離線是 NaN(不報錯),正式資料源會提供多時框。
  • numba 引擎未使用（走 --engine python）;正式部署請用 repo 釘選版本 numpy<2 / pandas<3 於 3.11 venv 重驗。

範例 1 · 單因子 MA 交叉（最小可跑） — example_single_ma.yaml

# =============================================================================
# 範例 1 —— 單因子 MA 交叉(最小可跑範例)
# =============================================================================
# 目的:證明 YAML → standard_bot(block path)最短路徑能端到端跑、且會產生交易。
# 執行:
#   驗證:  python -m cyqnt_trd.standard_bot.yaml_pipeline validate example_single_ma.yaml
#   回測:  python -m cyqnt_trd.standard_bot.yaml_pipeline run example_single_ma.yaml \
#             --input-json <klines.json>        # 離線用;正式用下面的 data.source
# =============================================================================

spec_version: "1.0"
target: standard_bot

strategy:
  id: btc_ema_cross_1h
  description: "BTC 1h EMA10/EMA30 交叉,多空對稱,pct 停損停利。"

run:
  mode: backtest                      # backtest | paper | live

data:                                 # 数据源
  symbol: BTCUSDT
  market_type: futures
  primary:
    interval: "1h"
    poll_interval: 3570               # 执行的周期(paper daemon 每次輪詢秒數)
  source:                             # 正式資料來源(離線測試可用 CLI --input-json 覆蓋)
    type: binance_rest                # binance_rest | historical_parquet | input_json

signals:                              # 信号计算
  indicators:
    ema_fast: { block: indicators.ema, input: close, params: { period: 10 } }
    ema_slow: { block: indicators.ema, input: close, params: { period: 30 } }
  entry:                              # 方向:同時給 long/short = 多空;只給 long = long-only
    long:
      cond: conditions.ma_cross_above
      args: [ema_fast, ema_slow]
    short:
      cond: conditions.ma_cross_below
      args: [ema_fast, ema_slow]

sizing:                               # 仓位决策
  size: 0.95                          # 每筆投入權益比例 (0,1]

risk:                                 # 风控
  exit:
    type: pct_stop_tp
    stop_pct: 0.02
    tp_pct: 0.04
    max_bars: 96
  fees: { commission_bps: 4.0, slippage_bps: 2.0 }

backtest:                             # run.mode=backtest 用
  initial_capital: 10000
  execution_model: next_bar_open

範例 2 · 多因子 + 巢狀（實際會跑出交易） — example_multi_factor.yaml

# =============================================================================
# 範例 2 —— 多因子 + 巢狀組合(完整能力展示,且實際會跑出交易)
# =============================================================================
# 展示:
#   * 巢狀組合:any_of( all_of(趨勢腿...), 突破腿 ) — 任意深度
#   * 多因子:EMA 交叉 + ADX 趨勢強度 + RSI 過熱過濾 + 突破
#   * tuple 輸出指標:adx 回傳 (adx, +di, -di),用 output: 0 取 adx
#   * 宣告式出場:atr_stop_tp(ATR 動態停損停利)
#   * paper trade;切 live 時用 risk.live_guards
# 執行:
#   驗證:  python -m cyqnt_trd.standard_bot.yaml_pipeline validate example_multi_factor.yaml
#   回測:  python -m cyqnt_trd.standard_bot.yaml_pipeline run example_multi_factor.yaml \
#             --input-json <klines.json>
#   (paper) 把 run.mode 改成 paper;(live) 改成 live 並填 risk.live_guards
# =============================================================================

spec_version: "1.0"
target: standard_bot

strategy:
  id: btc_multi_factor_nested_1h
  description: "BTC 1h 多因子:趨勢腿(EMA金叉+ADX+RSI不過熱)或 突破腿(30根新高),ATR 出場。"

run:
  mode: backtest                      # 改 paper / live 即切換模式(見檔尾)
  # duration_end_at: "2026-08-01T00:00:00Z"   # live 必填:session 時長上限

data:
  symbol: BTCUSDT
  market_type: futures
  primary:
    interval: "1h"
    poll_interval: 3570
  source:
    type: binance_rest
  # htf:                              # (可選)高周期上下文;會掛上 _htf_<tf>_sma_<period> 欄位
  #   - { interval: "4h", sma_period: 200 }   # 條件可用 args: [df, "_htf_4h_sma_200"]

signals:
  indicators:
    ema_fast: { block: indicators.ema, input: close, params: { period: 12 } }
    ema_slow: { block: indicators.ema, input: close, params: { period: 26 } }
    rsi14:    { block: indicators.rsi, input: close, params: { period: 14 } }
    adx14:    { block: indicators.adx, input: df, params: { period: 14 }, output: 0 }

  entry:
    long:                             # 巢狀:趨勢腿 OR 突破腿
      any_of:
        - all_of:
            - { cond: conditions.ma_cross_above, args: [ema_fast, ema_slow] }
            - { cond: conditions.adx_trending,   args: [adx14], params: { threshold: 18.0 } }
            - not: { cond: conditions.rsi_overbought, args: [rsi14], params: { threshold: 78.0 } }
        - { cond: conditions.breakout_high, args: [df], params: { lookback: 30 } }
    short:
      any_of:
        - all_of:
            - { cond: conditions.ma_cross_below, args: [ema_fast, ema_slow] }
            - { cond: conditions.adx_trending,   args: [adx14], params: { threshold: 18.0 } }
            - not: { cond: conditions.rsi_oversold, args: [rsi14], params: { threshold: 22.0 } }
        - { cond: conditions.breakout_low, args: [df], params: { lookback: 30 } }

sizing:
  size: 0.5

risk:
  exit:
    type: atr_stop_tp
    atr_period: 14
    stop_mult: 2.0
    tp_mult: 4.0
    max_bars: 120
  fees: { commission_bps: 4.0, slippage_bps: 2.0 }
  live_guards:                        # run.mode=live 時必填
    max_notional: 200
    notional_fraction: 0.95

backtest:
  initial_capital: 10000
  execution_model: next_bar_open

規格模板 · strategy.schema.yaml（完整欄位） — strategy.schema.yaml

# =============================================================================
# Strategy Spec v1 — 規格模板 / Schema(標的:cyqnt_trd/standard_bot,block path)
# =============================================================================
# 一份 YAML = 一個策略。它被 yaml_pipeline 編譯成 standard_bot 的 block strategy
# (make_signals(df) → (long, short)),並用 --engine python 在 backtest / paper /
# live 三條路上跑「完全相同」的訊號邏輯。
#
# 指令:
#   驗證:  python -m cyqnt_trd.standard_bot.yaml_pipeline validate  strategy.yaml
#   執行:  python -m cyqnt_trd.standard_bot.yaml_pipeline run       strategy.yaml
#
# 型別標記:<str> <int> <float> <bool> <dur>=1h/4h/1d  [..]=清單  {..}=物件  ?=可選
# =============================================================================

spec_version: "1.0"
target: standard_bot                  # 固定

strategy:
  id: <str>                           # 策略唯一 ID(→ --strategy)
  description: <str>?

# --- 真實交易 / paper trade ----------------------------------------------------
run:                                  # 真实交易 / paper trade
  mode: <backtest|paper|live>
  # backtest → mvp_backtest --engine python(一次性歷史回測)
  # paper    → mvp_paper_daemon --engine python(長時間模擬交易,不下真實單)
  # live     → paper daemon(訊號源) + mvp_live_executor(真實下單);見檔尾安全規則
  duration_end_at: <str>?             # ISO8601;run.mode=live 必填(session 時長上限)

# --- 數據源 + 每個數據源拉取週期 ------------------------------------------------
data:                                 # 数据源 / 每个数据源拉取周期
  symbol: <str>                       # e.g. BTCUSDT
  market_type: <spot|futures>
  primary:
    interval: <dur>                   # 主決策週期,e.g. "1h"
    poll_interval: <int>?             # 执行的周期:paper daemon 每次輪詢秒數(預設 3570)
  source:                             # 正式資料來源;離線測試可用 CLI --input-json 覆蓋
    type: <binance_rest|historical_parquet|input_json>
    # binance_rest       →(無額外欄位)線上抓 K 線
    # historical_parquet → dir/<...> + storage_timeframe? + download_missing? + start_ts?/end_ts?
    # input_json         → path: <str>(單一 kline JSON,離線)
    dir: <str>?
    storage_timeframe: <dur>?
    download_missing: <bool>?
    start_ts: <int>?
    end_ts: <int>?
    path: <str>?
  htf:                                # 每個高周期一條(每个数据源拉取周期);可選
    - { interval: <dur>, sma_period: <int> }
    # 會在 df 掛上欄位 _htf_<interval>_sma_<period>(lookahead-safe),
    # 條件可用 args: [df, "_htf_4h_sma_200"] 引用。

# --- 信號計算 + 方向 -----------------------------------------------------------
signals:                              # 信号计算
  indicators:                         # 命名的指標(factors);之後被條件引用
    <name>:
      block: <str>                    # "<module>.<fn>",module ∈
                                      #   indicators|conditions|entry|patterns|
                                      #   smc_structure|smc_liquidity|verdicts|scoring
      input: <close|open|high|low|volume|df|<name>>?   # 第一個參數(預設 close;
                                      #   若 block 第一參數是 df 會自動傳 df)
      params: { <k>: <v> }?           # 其餘 kwargs
      output: <int>?                  # 若 block 回傳 tuple(macd/adx/donchian/bollinger),取第幾個

  entry:                              # 方向:給 long/short = 多空;只給 long = long-only
    long: <node>?
    short: <node>?
    # <node> 可任意巢狀,五種形態:
    #   { all_of: [<node>, ...] }                        # 全部成立
    #   { any_of: [<node>, ...] }                        # 任一成立
    #   { not: <node> }                                  # 反相
    #   { exclude_when: { base: <node>, exclusions: [<node>, ...] } }
    #   { cond: "conditions.xxx", args: [<ref>, ...], params: {..} }   # 葉節點
    # <ref> = 指標名 / df 欄位名(close/high/...) / 字面 "df"

# --- 倉位決策 ------------------------------------------------------------------
sizing:                               # 仓位决策
  size: <float>                       # 每筆投入權益比例,(0,1](預設 1.0)

# --- 風控(出場 + 費用 + live 護欄)--------------------------------------------
risk:                                 # 风控
  exit:                               # 宣告式出場(→ strategy.register exit_cfg)
    type: <time_only|pct_stop_tp|atr_stop_tp|atr_trailing_stop|ma_cross_exit|opposite_signal>
    # time_only:          { max_bars }
    # pct_stop_tp:        { stop_pct, tp_pct, max_bars? }
    # atr_stop_tp:        { atr_period, stop_mult, tp_mult, max_bars? }
    # atr_trailing_stop:  { atr_period, trail_mult, max_bars? }
    # ma_cross_exit:      { period, ma_type, max_bars? }
    # opposite_signal:    { max_bars? }(預設:靠反向訊號出場)
  fees: { commission_bps: <float>?, slippage_bps: <float>? }   # backtest/paper
  live_guards:                        # run.mode=live 時必填
    max_notional: <float>             # 單筆名目硬上限(USDT)
    notional_fraction: <float>?       # 下單佔可用餘額比例(預設 0.95)

# --- 回測參數(run.mode=backtest 用)------------------------------------------
backtest:
  initial_capital: <float>?           # 預設 10000
  execution_model: <close_fill|next_bar_open>?   # 預設 next_bar_open(較真實)

# =============================================================================
# 附錄:常用可組合 blocks(全部可在 signals 內排列組合;完整清單見 docs/block_registry.json)
